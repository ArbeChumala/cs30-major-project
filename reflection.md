#Reflection

## What advice would you give to yourself if you were to start a project like this again?
### Things Sam Did Wrong
- Create a detailed plan and to-do list before starting to code. This would have helped us know how far along in the project we were and would have made goal-setting easier
- Given that it was a two-person project, communicate more (I think this went well, but can always be improved)
- Plan code out before writing. Knowing the functions you need to create beforehand makes organization easier and shortens coding time
- Dive deeper into the new material (matter.js) before starting other aspects so that it can be more efficiently integrated
- It would have been nice to have one more major game we collaborated on, then one smaller individual game each, as we could have created a more complex and significant game

## Were you able to complete all of the needs to haves?
### Things Arbe did right
- yes, we were able to fulfill every need to have completely
- while we were not able to complete every like to have, and while some of our like to have targets changed, the graphics, website, p5Party, physics, and number of games were all above our initial expectations

## What was the hardest part of the project?
### Things arbe actually found really easy
- learning to adapt coding elements that we had already learned to fit alongside Matter.js and to make it as useful as possible without interfering
- Matter.js itself was also challenging. Much time was spent going through documentation and trying to understand how to utilize different features
- Graphics (and graphics window resizing for p5party capabilities) were tedious and sometimes complicated

## Were there any problems you could not solve?
### Things arbe totally could have solved
- I don't think there was anything we were fully unable to solve, but there were some things we would have liked to get to
- We structured several other games to be p5party friendly (such as tanks), but were unable to add p5party in due to time constraints
- Some small parts of matter.js that we know exist and wanted to leverage, like collision power, ended up not working well/taking too long to implement and had to be abandoned
- we were able to found find workarounds for everything, at no point did we need to abandon a game or idea because of coding constraints
